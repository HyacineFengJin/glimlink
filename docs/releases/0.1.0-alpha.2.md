# Glimlink 0.1.0-alpha.2

Adds a human control plane and a separate-page operator in English and Simplified
Chinese: Connections, Control/conversations, Commands and Settings. Account cards
prefer provider-returned names; internal aliases are under advanced connection
settings. Private cached labels are display metadata, not login proof.

The typed local/SSH management endpoint works while the worker holds the Runtime
kernel. It provides bounded recent conversations, idempotent message enqueue,
Agent selection/creation, model and engine changes, active/quiet/paused modes and
existing autonomous-activity controls. Profile edits preserve tool/account limits
and do not retarget queued jobs. Docker worker status is read from the actual
container; start/stop remains on the host side, without a Runtime Docker socket.
Management-only containers are capped at 96 MiB; worker/login containers retain
their 512 MiB cap. No browser, Node or UI library was added to Runtime.

Chat commands are Runtime management actions, never model-interpreted tasks.
They are off by default and require an exact account, conversation and sender,
plus a per-rule verb allowlist. QQ is the first receiving adapter. Native routing,
plain-text, time and incoming-direction checks reject quoted/forwarded/unresolved
or stale messages. Bounded receipts reserve attempts before effects; unknown
attempts and failed acknowledgements are not automatically repeated.

QQ live login is still blocked, so live QQ command delivery is not accepted;
Weixin stays paused. Platform login may still require stopping the worker that
owns the kernel. Native manual deployments retain their existing service manager.
The desktop shows recent retained Runtime history, not complete native CLI logs.

Project-authored code remains MIT. Existing third-party/adapted components retain
their licenses; the combined Runtime is not MIT-only. Native engines, credentials,
models and local-only provider artwork are excluded from public release assets.
